🗺概要と全体像

Difyは強力なAIワークフロープラットフォームですが、社内ドキュメントをナレッジベースに登録するには 通常クラウドストレージやDify組み込みのベクトルDB（Weaviateなど）を使います。 しかし「すでにあるファイルサーバーのドキュメントをそのまま使いたい」「外部サービスにデータを渡したくない」 といったケースでは、外部ナレッジベースAPI機能が有効です。

本記事では、ローカルのPDF・Word・PowerPointをベクトル化してChromaDBに保存し、 Difyの外部ナレッジベースAPIとして提供する仕組みを一から構築します。 すべてローカルで完結するため、データが外部に出ることはありません。

📥ingest.py — ドキュメントをDBに取り込む

ingest.py は、docsフォルダ内のドキュメントを読み込み、 テキストをチャンクに分割し、ベクトル化してChromaDBに保存します。 一度実行すれば chroma_db/ ディレクトリにデータが永続化されます。

python ingest.py 
# ① 各ファイル形式に対応したローダー関数
from pypdf import PdfReader
from docx import Document as DocxDocument
from pptx import Presentation
import openpyxl

def load_pdf(path):
    reader = PdfReader(path)
    return "\n".join(page.extract_text() or "" for page in reader.pages)

def load_docx(path):
    doc = DocxDocument(path)
    return "\n".join(p.text for p in doc.paragraphs if p.text.strip())

def load_pptx(path):
    prs = Presentation(path)
    texts = []
    for slide in prs.slides:
        for shape in slide.shapes:
            if hasattr(shape, "text") and shape.text.strip():
                texts.append(shape.text)
    return "\n".join(texts)

# ② 拡張子とローダーのマッピング
LOADERS = {
    ".pdf":  load_pdf,
    ".docx": load_docx,
    ".pptx": load_pptx,
    ".xlsx": load_xlsx,
}

# ③ テキスト分割（日本語対応）
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,      # 1チャンクの最大文字数
    chunk_overlap=50,   # チャンク間のオーバーラップ
    separators=["\n\n", "\n", "。", "、", " ", ""],
)

# ④ 多言語対応の埋め込みモデル
EMBED_MODEL = "intfloat/multilingual-e5-small"
embeddings = HuggingFaceEmbeddings(
    model_name=EMBED_MODEL,
    encode_kwargs={"normalize_embeddings": True},
)

# ⑤ ChromaDBに保存
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",
    collection_name="dify_rag",
)

コードのポイント解説

ポイント説明
① ファイル形式ごとのローダー PDF・DOCX・PPTX・XLSXをそれぞれ専用ライブラリで解析。拡張子でローダーを振り分ける設計なので、新形式の追加も容易。
③ 日本語対応の分割 separatorsに「。」「、」を含めることで、日本語の文節を考慮した自然な分割を実現。
④ multilingual-e5-small 日本語・英語・中国語などに対応したHuggingFaceの多言語埋め込みモデル。サイズが小さく（~117MB）、CPUでも高速に動作する。
⑤ ChromaDB永続化 persist_directoryを指定することで、プロセスを終了してもデータが保持される。再インデックス不要。

🚀api.py — Dify互換APIサーバー

DifyはRAG検索を外部APIに委譲できる「外部ナレッジベース」機能を持っています。 このAPIは POST /retrieval エンドポイントに特定のリクエスト/レスポンス形式を期待します。

Difyが期待するAPI仕様

項目詳細
メソッドPOST /retrieval
認証Authorization: Bearer <API_KEY>
リクエスト{"query": "...", "retrieval_setting": {"top_k": 5, "score_threshold": 0.5}}
レスポンス{"records": [{"content": "...", "score": 0.95, "title": "...", "metadata": {}}]}
python api.py 
from fastapi import FastAPI, Request
from fastapi.responses import JSONResponse
from pydantic import BaseModel

# APIキーは環境変数で設定（デフォルト: dify-rag-secret）
API_KEY = os.environ.get("RAG_API_KEY", "dify-rag-secret")

app = FastAPI(title="Dify RAG API")

# 起動時に一度だけモデルとDBをロード（毎リクエストではロードしない）
embeddings = HuggingFaceEmbeddings(model_name="intfloat/multilingual-e5-small")
vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
    collection_name="dify_rag",
)

# Difyが期待するリクエスト/レスポンス型定義
class RetrievalRequest(BaseModel):
    knowledge_id: Optional[str] = None
    query: str
    retrieval_setting: RetrievalSetting = RetrievalSetting()

class Record(BaseModel):
    content: str
    score: float
    title: str
    metadata: dict

# Bearer認証ミドルウェア
@app.middleware("http")
async def verify_api_key(request, call_next):
    auth = request.headers.get("Authorization", "")
    if not auth.startswith("Bearer ") or auth[7:] != API_KEY:
        return JSONResponse(status_code=403, content={"error": "Unauthorized"})
    return await call_next(request)

# メイン検索エンドポイント
@app.post("/retrieval")
def retrieval(req: RetrievalRequest):
    results = vectorstore.similarity_search_with_relevance_scores(
        query=req.query,
        k=req.retrieval_setting.top_k,
    )
    records = [
        Record(
            content=doc.page_content,
            score=round(score, 4),
            title=doc.metadata.get("source", "unknown"),
            metadata=doc.metadata,
        )
        for doc, score in results
        if score >= req.retrieval_setting.score_threshold
    ]
    return {"records": records}

2

「外部ナレッジベースAPIを接続する」ボタンをクリックし、以下を入力します。

設定項目入力値

エンドポイントに /retrieval を含めないでください。Difyが自動的に付加します。

3

外部ナレッジベースを作成してアプリに紐付ける

登録したAPIを使って外部ナレッジベースを作成し、Difyのアプリ（チャットボットやワークフロー）のナレッジソースとして設定します。

🔒【ハマりポイント】SSRFプロキシの問題と解決策

DifyにはSSRFプロキシ（Squid）が内蔵されており、 デフォルトでプライベートIPアドレスへのリクエストを全てブロックします。 host.docker.internal はホストマシンのIPに解決されるため、これに引っかかります。

⚠️
エンドポイントの設定は正しいのに「Failed to save/update External API」と表示される場合、 ほぼ確実にSSRFプロキシによるブロックが原因です。

解決手順

1

コンテナからホストのIPを確認する

$ docker exec docker-api-1 getent hosts host.docker.internal
192.168.65.254  host.docker.internal

このIPが属するサブネット（通常 192.168.65.0/24）を許可します。

2

~/dify/docker/.env を編集する

env ~/dify/docker/.env 
# 変更前
SSRF_PROXY_ALLOW_PRIVATE_IPS=

# 変更後
SSRF_PROXY_ALLOW_PRIVATE_IPS=192.168.65.0/24
3

Difyを再起動する

$ cd ~/dify/docker
$ docker compose down && docker compose up -d

🎨Tips・カスタマイズ

APIキーを変更する

デフォルトのAPIキー dify-rag-secret は環境変数で変更できます。

$ RAG_API_KEY=my-secret-key python api.py

ドキュメントを追加・更新する

docs/ フォルダにファイルを追加したら、ingest.py を再実行するだけです。ChromaDBは上書き更新されます。

チャンクサイズの調整

検索精度が低い場合は chunk_size を調整してみてください。長い文書には大きめ（800〜1000）、短い箇条書きには小さめ（200〜300）が向いています。

ユースケースchunk_sizechunk_overlap
技術マニュアル・長文800〜1000100
社内規定・箇条書き200〜30030
プレゼン資料（デフォルト）50050

score_thresholdの調整

検索結果が返ってこない場合は score_threshold を下げてみてください（例: 0.5 → 0.3）。逆に無関係な結果が混じる場合は上げます。
